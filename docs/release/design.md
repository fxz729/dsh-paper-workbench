# 发布设计与验证策略

**目标**：独立公开仓库、预构建 DSH 安装包、中文功能文档、真实脱敏截图和可安装的自定义索引，重点覆盖文献管理工具。

**实现选择**：保留现有业务逻辑，抽取当前维护的 JavaScript 核心为 `src/`，以本地锁定依赖构建。更换包名、仓库身份与客户端注册 ID；保持库目录、稳定 ID、会话定位、路由和 preset 兼容。新包与上游在同一 profile 中保持一份启用。

**两种分发**：桌面插件页接受 Release `.tgz` 完整 URL；原生索引采用 format 1、固定 40 位 Git commit，Git 提交携带运行产物。Release 提供 SHA-256 校验和。社区目录另有仓库年龄和审核要求，状态独立记录。

**隐私与许可**：只抽取运行代码、维护源码、静态资源、自产演示样例及所需许可。排除用户 PDF、会话、墨迹、密钥、私人许可证、历史部署备份。应用保留 MIT；tldraw SDK 保留原许可证、生产校验和水印规则，用户自备许可。

**有限验证**：文献管理七文件定向测试；其余可移植 Node 回归；隔离实际生产组件/路由/本地 runtime 浏览器演示；npm dry-run 文件清单检查；tarball 在临时目录中无开发依赖安装并使用实际 DSH SDK 注册工具。真实收费请求数保持零。实际运行结果集中记录在验证说明中，不把替身场景描述成完整 Desktop 验收。
