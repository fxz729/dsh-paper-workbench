# 使用指南

[返回首页](<../README.md>) · [配置说明](<configuration.md>)

## 1. 建库与导入

在文献树中创建根库，再通过库的菜单创建子库。库备注保存在本地，用来记录选题范围、阅读次序或筛选标准。

### 图形界面导入

- **上传 PDF**：选择目标库后上传文件。
- **导入文件夹**：递归收集目录中的 PDF，预览目标专题、同名冲突与跳过项。默认使用文件夹名作为专题，子目录中的 PDF 汇入同一目标专题，不照搬为嵌套库。
- 同名文件与 `-en`／`-zh`／`-dual` 译文产物按导入规则跳过；导入保留外部原目录和原文件。
- 导入完成后核对成功／失败提示。可按需要另建子库，再分别导入。

### 用模型管理文献

以下示例是给模型的自然语言指令；实际 UUID、版本、计划与操作标识由工具返回结果提供：

> 列出文献库及备注。创建“实验方法”子库，把我指定的 PDF 复制进去。遇到同名文件就跳过。

> 给这个库保存备注：“先读基线方法，再读复现实验”。

> 我已给出这篇论文的摘要和书目信息，请本地保存，不调用摘要生成 API。

`library_manage` 的动作与边界：

| 动作 | 输入重点 | 行为 |
| --- | --- | --- |
| `list` | 无 | 返回库树与文献条目 |
| `create_collection` | `name`、可选 `parentId`／`note`、`operationId` | 创建库；省略父库时创建根库 |
| `update_collection` | `collectionId`、备注或名称、`expectedRevision` | 备注本地保存；名称先计划，再携 `planId` 与 `operationId` 经确认应用 |
| `import_pdfs` | `collectionId`、`sources`、`operationId` | 复制导入外部 PDF；原件保留，同名不覆盖；可同时提交已知摘要与书目信息 |
| `get_paper` | `paperId`，或查询库详情时的 `collectionId` | 读取详情与元数据版本 |
| `update_paper` | `paperId`、`summaryText`／`bibliography`、`expectedRevision` | 把当前模型已知内容本地保存，无额外生成请求 |
| `plan_enrichment` | `paperId`、`features: ["summary", "name"]` 的所需子集 | 生成计划，供检查输入量、模型和处理范围 |
| `run_enrichment` | `planId`、`operationId` | 经宿主费用确认后执行 |
| `set_automation` | `autoSummary`、`autoName`、`expectedRevision` | 全局自动摘要／命名设置；新开启项需要确认费用 |
| `job_status` | 可选 `paperId` | 查询任务状态 |

先用返回的 `paperId`／`collectionId` 定位，写入前读取当前 revision；版本冲突时刷新并核对新内容。同一次操作重试复用原 `operationId`。费用与改名确认绑定具体工具调用，模型自行填入 `confirmCosts: true` 仍需通过宿主授权。

工具没有删除 action，也不接收任意配置修改。图形界面的删除操作另有计划预览与确认流程。

## 2. 摘要与自动命名

点击论文旁的“文献摘要”入口，可阅读摘要、查看任务状态和执行按需生成。**“生成／重新生成／重试生成”是一次 API 操作的费用授权入口**，请先配置端点并阅读界面提示。处于“查询状态”的操作只查询已有任务。

库旁的“库备注”入口提供本地编辑；保存前的版本检查用于保留并发修改。

### 全局自动摘要／命名

两项开关默认关闭，作用于整个文献库及未来新建的子库：

- **自动摘要**：仅处理启用后符合首次发现／导入资格的新文献；已有模型或手工摘要受到保护。
- **自动命名**：根据论文的作者、年份与原题等书目信息生成名称，实际物理改名 PDF 及受管理的关联产物。
- 启用时已有文献、重启期间补盘点的旧文件、普通重扫与改名不回填收费任务。来源或语言等条件不明时进入待核实状态。
- 启用前开始复制、启用后才稳定的文件保留首次观察资格；单凭较新的文件时间或入库序号不会升级为自动费用许可。

缺字段、命名冲突、版本变化或已有人工内容时，任务可能进入 `needs-review`。检查候选后再决定采用。`request-unknown` 表示请求可能已发送而结果尚未确认，先核对服务端账单／任务；明确重试会再次发送请求。

### 改名与关联

使用界面或工具的计划／确认流程改名。`paperId` 与 `collectionId` 保持稳定，受管理的 PDF 变体、转录、批注和墨迹等按精确清单移动，伴读聊天按真实 session ID 保持论文关联。

外部文件管理器直接改名或复用旧名称会绕开该事务。遇到旧名称有多个历史归属时，刷新后按 UUID 操作。宿主已有工作区路径、进程 cwd 与插件的论文身份是不同层次；改名预览中的会话影响和后续提示应逐项核对，已有终端需自行确认所在目录。

## 3. 阅读、聊天与检索

- **文献工作台**：文献树、阅读器与 DSH 原生聊天协同显示。
- **普通工作区**：保留日常工作界面，通过右侧伴读阅读文献。
- **选文提问**：把论文选区交给 DSH 会话；回答由该会话当前 provider／模型产生。
- **检索**：`transcribe_pdf` 提取或读取转录缓存，`search_paper` 返回相关原文片段；可选 OCR、embedding 与重排分别配置。
- **学习记录**：`study_progress` 查看计划与成绩，`study_update` 记录计划、完成步骤及检验结果。

模型总结与翻译建议应回到原文核对，尤其是数字、公式和结论范围。

## 4. 注释与手写墨迹

阅读器提供注释与可选 tldraw 墨迹层。原文、中文版、双语版各有独立墨迹；切换变体后请确认当前页与内容，分别保存。

生产使用 tldraw 5.6.0 需自行取得有效许可，在阅读器许可入口输入自己的 key。仓库不分发私人许可，也不关闭 SDK 校验。详见[配置说明](<configuration.md#tldraw-墨迹许可>)。

改名、删除和导航会协调阅读器保存。遇到保存版本冲突、恢复草稿或文件占用提示，先处理当前草稿，再重试；不要手工覆盖墨迹旁文件。

## 5. 翻译与队列

整篇翻译使用独立配置的 OpenAI 兼容端点，经 BabelDOC 生成译本。首次使用可能需要下载 Python 运行环境、BabelDOC 及辅助资源，耗时随网络和文献而变。

批量翻译页提供：

- 待翻译／已翻译／全部筛选；默认排除已验证译本和活动队列条目。
- 按专题全选与半选；只选择当前可见候选。搜索或筛选变化清空选择。
- 大批量分段提交；部分失败保留尚未成功提交的选择。
- 暂停、继续、失败重试和保留失败记录的清理。
- 损坏、不明、源文件变化等待确认状态单列，普通批量操作不覆盖这些产物。

### 自动翻译的两层规则

自动翻译独立于自动摘要／命名，默认关闭：

| 规则 | 范围 |
| --- | --- |
| 全局自动翻译 | 当前与未来文献库中，启用后符合资格的新英文 PDF |
| 按文献库开启 | 指定 `collectionId` 的新英文 PDF；子库有自己的规则，不由父库单独授权继承 |

开启时有费用提示，不回溯历史文献。全局开启时按库控件显示全局状态。**关闭自动规则停止新增入队；暂停队列控制已经入队任务的后续执行。** 当前正在执行的文献按队列与取消提示处理。关闭页面不会等同于暂停后台队列。

## 6. 删除与恢复

文献树的删除／清空先读取服务端计划，展示受影响文件、保留内容与回收站信息；专题操作还要求输入名称确认。操作按固定 ID 与计划执行，失败或版本变化时保留阅读器与草稿，按提示重新预览。

库删除／清空保持非递归语义：含子库或未知条目时先返回冲突。请分别处理子库和待核实文件。成功后目录／受管理文件进入回收区，历史 UUID、元数据与聊天记录仍保留可追溯关系。

恢复时先备份当前库及回收区，核对操作回执与回收站相对位置；若原位置已有其他文件，保留双方并人工处理。遇到部分回滚提示，按列出的文件与恢复位置操作，避免把 `.trash` 或记录文件直接清空。

## 7. 从上游迁移

1. 完整备份文献库，包括隐藏索引、旁文件与回收区；另按你的凭据管理方式备份配置。
2. 在目标 profile 中停用上游插件，确认只启用一份文献插件。
3. 安装本插件，使用原 `dataDir`；默认仍为 `~/.dsh-paper-reader/data`。
4. 核对库树、论文、摘要、批注与聊天关联。先用副本验证，再启用任何自动费用功能。
5. 旧引用歧义、索引损坏或不明的请求结果按待核实提示处理，保留证据文件。

改回旧版前也需保留当前备份；本版创建的稳定身份和事务状态应完整保存，旧版对新增状态的读取能力需另行验证。
